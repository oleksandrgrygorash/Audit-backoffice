# Аудит сервісів Back Office — збір відповідей у Google Sheets

**Дата:** 2026-06-29
**Статус:** дизайн затверджено, готується план реалізації

## Контекст

Форма опитування «Аудит сервісів Back Office» (Quarks) — один статичний
`index.html`, розміщений на GitHub Pages
(`https://oleksandrgrygorash.github.io/Audit-backoffice/`). Форма оцінює
сервіси Back Office за двома шкалами 1–4 (Користь і Важкість) з опцією
«не користуюсь». Збір відповідей наразі НЕ підключено — у футері стоїть
note про те, що рішення відкрите. Дизайн і верстка форми вважаються
готовими й змінюватися не повинні.

## Мета

1. Підключити збір відповідей у Google Sheet.
2. Фіналізувати наповнення (список сервісів).
3. Провести анонімне опитування й зібрати дані для подальшого аналізу.

## Затверджені рішення

| Питання | Рішення |
|---|---|
| Транспорт даних | Google Apps Script Web App |
| Формат таблиці | Широкий: один рядок = одна відповідь (одна людина) |
| Ідентифікація | Повністю анонімно (без імені та email) |
| Обсяг | ~9–20 сервісів, згрупованих за owner |

## Архітектура

```
Браузер (GitHub Pages, index.html)
   │  fetch POST, Content-Type: text/plain, тіло = JSON payload
   ▼
Google Apps Script Web App (doPost, /exec)
   │  appendRow()
   ▼
Google Sheet  ──→  аналіз (зведені таблиці, графіки)
```

- Форма лишається на GitHub Pages. Жодних змін у CSS/верстці.
- У прив'язаному до Sheet Apps Script реалізуємо `doPost(e)`, який парсить
  JSON-тіло й дописує рядок. Публікація як Web App з доступом «Anyone».
- `Content-Type: text/plain` обрано навмисно, щоб уникнути CORS-preflight,
  який ламає прості POST з браузера на Apps Script. Користувач різниці не
  бачить.

## Структура даних

### Payload (форма → скрипт)

```json
{
  "submission_id": "20260629T141233-a8f3",
  "ts": "2026-06-29T14:12:33.000Z",
  "role": "Manager",
  "unit": "Soportio",
  "team": "Назва команди",
  "comment": "вільний текст",
  "answers": [
    { "id": "hire", "name": "Найм людини", "owner": "Talent Acquisition",
      "value": 3, "burden": 4 },
    { "id": "device", "name": "Техніка", "owner": "Operations", "na": true }
  ]
}
```

`submission_id` = timestamp + випадковий суфікс, генерується на клієнті.

### Аркуш Google Sheet (широкий формат)

Один рядок на відповідь. Колонки у фіксованому порядку:

```
timestamp | submission_id | role | unit | team | comment |
<сервіс 1> користь | <сервіс 1> важкість |
<сервіс 2> користь | <сервіс 2> важкість | ...
```

- Header-рядок створюється скриптом при першому запуску (або задається
  вручну) на основі фінального списку сервісів.
- Для відповіді «не користуюсь» в обидві клітинки сервісу пишемо `—`.
- **Прийнятий компроміс:** широкий формат прив'язаний до порядку й складу
  списку сервісів. Тому список `SERVICES` фіналізуємо ДО запуску й після
  старту збору не змінюємо (інакше колонки зсунуться).

## Зміни в index.html (тільки JS)

1. Додати константу `ENDPOINT` з URL Web App.
2. Генерувати `submission_id` у payload.
3. У `renderSummary` після показу підсумку асинхронно слати
   `fetch(ENDPOINT, { method:"POST", body: JSON.stringify(payload) })`.
4. Показувати тихий статус відправки:
   - успіх → «Збережено ✓»;
   - помилка → «Не вдалось зберегти автоматично — натисни „Скопіювати
     дані“ й надішли вручну» (fallback уже існує).
5. Прибрати footer-note про «рішення ще відкрите».
6. Рендер сервісів згрупувати за `owner` з підзаголовками-секціями
   (стиль існуючих елементів, без нових кольорів/шрифтів).

## Контент: список сервісів

- Поточні 5 сервісів — placeholder. Перший крок реалізації — фіналізувати
  масив `SERVICES` (по `{ id, name, desc, owner }`) разом з користувачем.
- Цільовий обсяг ~9–20, згруповані за функціями Back Office
  (Operations / HR / Talent Acquisition / Finance / Legal / IT тощо).
- Структура оцінювання не змінюється — дві шкали на сервіс.

## Проведення опитування

- Роздати одне посилання (GitHub Pages URL) у Slack / email.
- Анонімно, ~5 хв, адаптивно під будь-який пристрій.
- Відповіді в реальному часі падають у Sheet.
- Аналіз — у самій таблиці (зведені таблиці, графіки). Окремий
  аркуш-дашборд з автоформулами — опційно, поза цією спекою.

## Тестування

1. Локально відкрити форму, надіслати тестову відповідь → переконатись, що
   рядок з'явився у Sheet з правильними колонками й значеннями.
2. Кейс «не користуюсь» → обидві клітинки `—`.
3. Кейс недоступного endpoint → показ fallback-повідомлення, дані не
   губляться (доступне «Скопіювати дані»).
4. Очистити тестові рядки перед реальним запуском.
